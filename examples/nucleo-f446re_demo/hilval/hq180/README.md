# hilval hq180 on a NUCLEO-F446RE

Generated by the hil-validations bench gate for one bench run; do not edit.

Two STM32duino images for stm32duino/Arduino_Core_STM32 issue #1834: `Serial.write()` and `Serial.flush()` loop forever when they are called from an ISR or with interrupts disabled while a transmission is in progress.

* `before` is core revision 53560ef, unmodified.
* `after` is the same sketch on a copy of that core with `firmware/hq180/serial-poll-when-irq-blocked.patch` applied, which polls the UART interrupt handler by hand where it cannot run and aborts the hardware transfer when a flush timeout fires.

Both images run the same 17 cases, 20 repetitions each, one case per boot: `write()` with the 64-byte TX ring full, `flush()`, `flush(20)` and `flush(1)`, each in thread mode with interrupts enabled, in thread mode with PRIMASK set, inside a TIM3 update ISR at preemption priority 1 (the UART's own level) and inside one at priority 0 (which blocks SysTick too). A hang is ended by the independent watchdog; breadcrumbs stored in `.noinit` before each call are printed after the reset.

The images print raw measurements only: DWT cycle counts across the call, PRIMASK, BASEPRI and IPSR, the TX ring's head, tail and transfer size, the USART status and control registers, the reset flags, the clock configuration they measured with, and the case's own data lines. They print no verdict: the gate recomputes the baud-rate divider, the frame time and every deadline from those values and judges the bytes against the serial capture.

Run by [Agentic Hardware-in-the-Loop (Agentic HIL)](https://github.com/agentic-hil/agentic-hil): its test reactor flashes each image, resets the board with the serial port open and records what the image prints; `agentic-hil run-evidence` turns each run into a report a reader without the board can check.

Each image prints lines `H180 <kind> key=value ...` on USART2 (the ST-LINK virtual COM port, PA2/PA3, 115200 baud) and ends with `H180 done`; each plan in [plans/](plans/) waits up to 480 s for every line it waits for. The tests that sent the images judge the values in the serial log; the images print measurements, not verdicts.
